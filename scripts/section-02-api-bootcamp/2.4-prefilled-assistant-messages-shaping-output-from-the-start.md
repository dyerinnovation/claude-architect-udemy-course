## SLIDE 1: The Preamble Problem

**Visual**: Split screen. Left: a chat bubble showing Claude's response starting with "Sure! I'd be happy to help you extract that information. Here is the JSON you requested:" followed by actual JSON. Right: the same response starting cleanly with `{`. A red X on the left, a green checkmark on the right.

You've asked Claude to extract structured data and return JSON.

Instead you get: "Sure! Here's the JSON you asked for..."

Then the JSON.

That preamble is harmless in a chat app.

But in a production pipeline, it breaks your JSON parser immediately.

The fix is a technique called prefilling, and it's one of the most useful tools in your API toolkit. Scenario 6 from lecture 1.1 — Structured Data Extraction — is where this technique earns its keep.

Let's look at exactly how it works.

## SLIDE 2: What Is a Prefill?

**Visual**: A diagram of the messages array as a vertical list of labeled boxes. The boxes are: `user` (blue), `assistant` (green), `user` (blue), and then a final `assistant` box (green, highlighted with a glow) labeled "PREFILL — Claude continues from here." An arrow points from the bottom of the prefill box downward into a response stream.

The `messages` parameter in the API is just an array of turns, where each turn has a role of either `"user"` or `"assistant"`. To understand prefilling, look at it from two angles side by side.

[click]

On the left, the visualization. A normal conversation alternates user, assistant, user — and then Claude writes the next assistant turn. A prefill flips that final move: you end the array with your own assistant turn, and Claude continues from there.

[click]

On the right, the mechanic. Normally — last entry is `user`, Claude writes a fresh assistant turn. Prefill — last entry is `assistant`, and Claude continues from that exact character. The effect: Claude cannot add anything before your text. You control the very first token of the response.

## SLIDE 3: When Prefilling Is the Right Tool

**Visual**: A four-item icon list on a clean white background. Each item has a small icon and a short label: (1) curly braces icon — "Force JSON output", (2) speech bubble with X — "Eliminate filler preamble", (3) code block icon — "Start a code fence", (4) theater mask icon — "Lock in a persona or voice".

Prefilling is useful in four common situations. All of them share the same mechanic — you're not adding a special parameter, you're using the structure of the `messages` array itself.

[click]

First — force JSON to open with `{`. The single most common use case. Your downstream parser expects valid JSON from character one, and a prefill guarantees that.

[click]

Second — eliminate preamble. No more "Certainly!" or "Great question!" cluttering the response. The prefill skips straight to the content you want.

[click]

Third — open a code block. Prefill with three backticks and a language tag, and Claude writes Python code directly. No introduction, no explanation first.

[click]

Fourth — lock in a persona. Mid-conversation, you can prefill with a character's signature opener and Claude stays in voice — no immersion break.

## SLIDE 4: The Code — JSON Extraction Prefill

**Visual**: Dark-background code editor panel showing the full Python example below, with syntax highlighting. Three lines are highlighted in amber: the prefill message dict, the `content` value `"{"`, and the line accessing `response.content[0].text`. A sidebar note reads: "Claude completes the JSON from here."

Let's walk through a real prefill example end to end. We start the usual way — import anthropic and json, create the client, and define some unstructured input we want to turn into JSON. Nothing prefill-specific yet.

```python
import anthropic
import json

client = anthropic.Anthropic()

user_data = "Name: Alice Chen, Role: Staff Engineer, Team: Platform"

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=256,
    messages=[
        {
            "role": "user",
            "content": f"Extract the following into JSON with keys name, role, team:\n\n{user_data}"
        },
        {
            # Prefill: Claude will continue from this exact character
            "role": "assistant",
            "content": "{"
        }
    ]
)

# Re-attach the opening brace Claude was given, then parse
raw = "{" + response.content[0].text
result = json.loads(raw)
print(result)
```

[click]

Now the call itself — and this is where the prefill lives. Look at the messages array. The user turn asks for JSON. But the last entry has `role: "assistant"` with content of exactly one character — an opening curly brace. That single brace IS the prefill. Claude continues from that character — it cannot add a preamble before it.

[click]

Here's the detail that trips people up: the prefill text is NOT included in the response body. Claude returns only what it generated AFTER the prefill — so `response.content[0].text` starts with the second character of the JSON, not the opening brace. To reconstruct the full value, you prepend the prefill yourself. That's the `raw = "{" + ...` line. Now `json.loads()` works on the first try.

## SLIDE 5: Code Generation and Format Prefills

**Visual**: Two side-by-side code panels. Left panel shows a prefill of ` ```python\n ` with a label "Forces Python code block". Right panel shows a prefill of `"The answer is:"` with a label "Forces specific phrasing". Both panels have a downward arrow labeled "Claude continues here."

The same technique works for any output format you need to lock in.

For code generation, prefill with the opening fence and language tag.

```python
{
    "role": "assistant",
    "content": "```python\n"
}
```

Claude will now write Python code directly — no introduction, no explanation first.

[click]

For format control, prefill with the exact phrase you want to start the response.

```python
{
    "role": "assistant",
    "content": "The answer is:"
}
```

This eliminates any variation in how Claude opens its response.

It's especially useful when you're parsing outputs downstream with string operations.

## SLIDE 6: Prefills and Stop Sequences — The Power Pair

**Visual**: A flow diagram showing three stages left to right: a "Prefill" box (green, labeled "Controls the START"), a middle box showing Claude's generation in progress, and a "Stop Sequence" box (red, labeled "Controls the END"). An arrow runs through all three labeled "Clean, bounded output."

Prefills and stop sequences solve opposite halves of the same problem.

A prefill controls where Claude starts.

A stop sequence controls where Claude stops.

Together, they let you extract exactly what you want from a response.

[click]

Here's the pattern: prefill with an opening XML tag, stop at the closing tag.

```python
response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=512,
    stop_sequences=["</answer>"],
    messages=[
        {"role": "user", "content": "What is 12 * 8? Respond inside <answer> tags."},
        {"role": "assistant", "content": "<answer>"}  # prefill
    ]
)
# response.content[0].text contains only what's between the tags
```

The response will be the content between the tags — nothing before, nothing after.

That's a clean extraction with zero post-processing regex.

## SLIDE 7: Exam Tip

**Visual**: Amber callout box. Title: "Exam Tip". Icon: target/bullseye. Text: "There is no `prefill` parameter — it's just the messages array."

Exam Tip time. The headline is blunt — there is no `prefill` parameter. Two callouts make that concrete.

[click]

First, the distractor pattern. Candidates look for a dedicated `prefill` parameter in the API, or believe you need a special flag like `prefill=True` to enable this behavior. There is no such parameter. A distractor that invents one is plausible in a different API's context — which is exactly what makes it an almost-right trap on the exam.

[click]

Second, the entire mechanic — and it really is the entire mechanic. If the last message in the array has role `"user"`, Claude starts a fresh response. If it has role `"assistant"`, Claude continues from its content. That's it. Know that one rule cold and prefill questions on the exam are free points.

## SLIDE 8: Key Takeaways

**Visual**: Clean bullet list on light background. Title: "What to Remember".

Four things to hold onto from this lecture.

[click]

First — assistant-role last. A prefill is an `"assistant"` role message placed LAST in the `messages` array. Claude continues from its content, adding nothing before it. That's the whole technique in one sentence.

[click]

Second — not in the response body. The prefill text is NOT included in the response body. Claude returns only what it generated after the prefill, so you prepend the prefill yourself when reconstructing the full output.

[click]

Third — common uses. Force JSON to open with `{`. Eliminate preamble. Open code fences with a language tag. Lock in a persona mid-conversation.

[click]

Fourth — pair with `stop_sequences`. Prefill opens, stop sequence closes. The cleanest way to extract structured content with zero post-processing regex.
